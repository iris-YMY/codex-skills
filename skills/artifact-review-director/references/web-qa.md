# Website and interactive artifact QA

Use the owning website-building workflow and browser-based testing. If the project uses Sites, follow its build and hosting Skills.

## QA

- Confirm the project builds and the intended route loads without fatal errors.
- Check browser console and failed network/resource loads.
- Test primary navigation, links, buttons, forms, validation, success, error, loading, empty, and disabled states as applicable.
- Inspect desktop, tablet, and mobile layouts for overflow, clipping, unreadable text, broken images, and unusable controls.
- Check keyboard navigation, labels, focus visibility, semantic structure, contrast, and alternative text at an appropriate baseline.
- Confirm titles, metadata, favicon, social preview, and analytics or consent behavior when requested.
- Check performance-sensitive assets and obvious regressions without claiming a full performance or security audit.
- Remove test credentials, debug panels, placeholder copy, mock data, and environment leaks before publication.

## User review

Prefer a persistent browser preview. Supplement it with responsive screenshots and a short test-path summary. Invite feedback by route, viewport, component, and state.

Require explicit approval before deployment or other external publication. Deployment confirmation is separate from content/design review.
